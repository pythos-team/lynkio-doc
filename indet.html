🔁 Lynk Real‑Time Face‑Swap Streaming

How to use the binary WebSocket server, connect any client, and build your own pipeline

🌐 Overview

Lynk is a pure‑Python real‑time engine supporting HTTP, WebSocket, and UDP on the same port. The face‑swap system uses named binary events sent over WebSocket. A camera client sends raw video frames as a "video_frame" event; the server processes them with InsightFace and replies with a "swapped_frame" event.

┌──────────┐ WebSocket ┌──────────────┐ │ Client │ ◄──────────────────────► │ Lynk │ │ (camera) │ "video_frame" │ Server │ │ │ "swapped_frame" │ (face‑swap) │ └──────────┘ └──────┬───────┘ │ Multiprocessing worker (InsightFace)

This guide explains every piece from scratch – you can use our ready clients or write your own in any language.

📦 Binary Event Protocol

Every binary WebSocket frame is tagged with an event name so handlers can route it. The server and client libraries handle the header automatically.

Frame structure (big‑endian)

+----------------+-------------------+---------------------------+ | 2 bytes | event_name bytes | payload (raw data) | | (event name | (UTF‑8 encoded) | | | length) | | | +----------------+-------------------+---------------------------+

For example, to send a "video_frame" with 4‑byte ID + image:

# Python
name = "video_frame"
header = struct.pack("!H", len(name)) + name.encode()
full_payload = header + frame_id_bytes + image_bytes
await client.ws.send_binary(full_payload)   # generic binary

# Lynk client shortcut (does the header packing)
await client.ws.send_binary_event("video_frame", frame_id_bytes + image_bytes)

Any language that can write a WebSocket binary frame can implement this header.

🖥️ The Lynk Server (face_swap_server.py)

1. Import & Configuration

from lynkio import Lynk
app = Lynk(host="0.0.0.0", port=8765, protocol="TCP",
            max_message_size=640*480*3+1024)
app.enable_cors(["*"])

We use TCP mode because WebSocket runs on top of TCP. The max message size accommodates raw 640×480 BGR frames plus header.

2. Register a named binary event handler

@app.on_binary_event("video_frame")
async def on_video(client, data: bytes):
    # data = everything after the event name header
    frame_id = int.from_bytes(data[:4], 'little')
    image = np.frombuffer(data[4:], ...)
    # queue for processing
    frame_queue.put_nowait((client.id, image, frame_id))

The decorator strips the event name header – your handler only receives the payload you care about.

3. Background tasks (processor & sender)

@app.task
async def processor():
    while True:
        cid, frame, fid = await frame_queue.get()
        in_q.put((cid, frame, fid))          # to multiprocessing worker
        # collect results from out_q ...

@app.task
async def send_results():
    while True:
        await asyncio.sleep(0.005)
        # send back via send_binary_event()
        await app.send_binary_event(cid, "swapped_frame", payload)

Lynk automatically runs tasks when the server starts.

4. Multiprocessing worker

InsightFace runs in a separate process to avoid blocking the async loop. Data is exchanged with multiprocessing.Queue.

def worker_process(in_q, out_q):
    # load models (once)
    swapper = get_model("inswapper_128.onnx")
    ...
    while True:
        cid, frame, fid = in_q.get()
        # detect, swap
        out_q.put((cid, swapped_frame, fid))

📱 The Python Client (face_swap_client.py)

1. Connection‑first pattern

Always connect before opening the camera. Use a threading event to synchronise:

connected_event = threading.Event()
# Start network thread that sets connected_event after client.ws.connect()
if not connected_event.wait(timeout=10):
    print("Connection failed")
    return
cap = cv2.VideoCapture(0)   # now safe

2. Send frames as named binary events

raw = frame.tobytes()
msg = frame_id.to_bytes(4, 'little') + raw
await client.ws.send_binary_event("video_frame", msg)

3. Receive swapped frames

def on_swapped(data: bytes):
    frame_id = int.from_bytes(data[:4], 'little')
    img = np.frombuffer(data[4:], ...)
    display_queue.put(img)

client.ws.on_binary_event("swapped_frame", on_swapped)

🛠️ Building a Client in Any Language

You only need a standard WebSocket library. The binary event header is simple:

  1. Connect to ws://host:8765
  2. For sending a named event: 
    // JavaScript browser example
const encoder = new TextEncoder();
const name = "video_frame";
const nameBytes = encoder.encode(name);
const header = new DataView(new ArrayBuffer(2 + nameBytes.length));
header.setUint16(0, nameBytes.length, false); // big-endian
// Append name bytes and payload
const full = new Uint8Array(header.byteLength + nameBytes.length + payload.length);
full.set(new Uint8Array(header.buffer), 0);
full.set(nameBytes, 2);
full.set(payload, 2 + nameBytes.length);
websocket.send(full.buffer);
  3. For receiving, read the first 2 bytes to get the name length, then the name, then the rest is payload. Dispatch accordingly.

The same logic works in C++, Flutter, Go, etc. – any WebSocket client that supports binary frames.

🔍 Debugging Blank / No Connection

Server side

  • Enable logging: logging.basicConfig(level=logging.INFO)
  • Check for "Worker ready" – if missing, the model/source image path is wrong.
  • Look for "Received video frame" – if absent, the client isn't reaching the server.
  • Use ctx_id=-1 for CPU in WSL; ctx_id=0 for GPU.

Client side

  • The window shows raw camera feed if no swapped frames arrive – that proves camera + connection work.
  • Check terminal prints: "Connected", "Sent frame X", "Received swapped frame Y".
  • Ensure SERVER_HOST is correct (WSL2 IP or localhost with portproxy).

🧩 Adding More Streams (Audio, Controls)

Because we use named binary events, adding a second stream is trivial:

Server

@app.on_binary_event("audio_chunk")
async def on_audio(client, data):
    # data is raw audio bytes
    process_audio(data)

Client

await client.ws.send_binary_event("audio_chunk", mic_bytes)

Each stream stays independent – the video code doesn’t need to change at all.
